# Revisión de código — Folio

> Review de un agente senior de código (2026-11-03). Hallazgos verificados con archivo:línea sobre el código real; el #1 fue verificado en vivo contra la API de arXiv.

## Veredicto

Código base sólido y sorprendentemente maduro: concurrencia optimista bien hecha, aislamiento del compilador ejemplar y validación en todas las fronteras. Los 6 hallazgos verificados son puntuales pero dos son de pérdida silenciosa de datos/resultados (búsqueda arXiv y overwrite del .bib) y conviene arreglarlos antes de commit inicial. Nada estructural que obligue a rediseñar.

## Huecos de test

- **`DocumentStore.replaceFromServer`** (`document-store.ts:186`): cero tests — es exactamente el camino del hallazgo 2 (actualización del servidor con documento sucio). Un test con fake api lo habría cazado.
- **`replaceCiteKey`** (`citation-health.ts:136`): sin test pese a ser el motor de reescritura del "upgrade a versión publicada" (listas multi-clave, clave repetida, archivo sin coincidencias).
- **`removeBibEntry`** (`bibtex.ts:25`): sin test directo; el route de upgrade confía en que preserva el resto byte-a-byte.
- **`searchAllPapers`** (`papers.ts:344`): el merge round-robin con dedup por DOI no tiene test; `research.test.ts` solo cubre los mappers (por eso el encoding roto de arXiv pasó).
- **`enforceCiteKeys` con familia biblatex**: el test existente ("handles citep/citet variants") pararía justo antes del hueco del hallazgo 4 — añadir `\textcite` lo cubriría.
- **Puerta de concurrencia del compilador** (`server.ts:321`): el e2e es excelente en seguridad pero no lanza peticiones simultáneas > MAX_JOBS.
- **Route de restore de snapshots** (bucle multi-archivo + snapshot undo + propagación del 409): sin test de integración.

## Patrones bien hechos (no romper)

1. **Concurrencia optimista end-to-end**: `baseVersion` en cada PUT, 409 devuelve la copia del servidor, `saveFile`/`createFile` re-verifican los caps **dentro** de la transacción con `pg_advisory_xact_lock`, y el índice único `files(project_id, path)` respalda el `onConflictDoNothing` (`src/lib/projects.ts:245-333`, `src/lib/db/schema.ts:75`). El document-store cliente encaja con ello (salvo el caso del hallazgo 2).
2. **Aislamiento del compilador con re-validación**: el servicio nunca confía en el llamador (`safePath` propio, round-trip base64, `timingSafeEqual` del token), `latexmk` con `-no-shell-escape`, `openin/openout_any=p`, procesos detached matados por grupo al timeout — y todo ello **verificado por e2e** incluyendo `\write18` y escapes de ruta (`services/latex-compiler/compile.e2e.test.ts:114-184`).
3. **Higiene de prompt-injection + honestidad estructural del modelo**: system prompts marcan documento y log como datos no confiables, y las citas del agente se limitan por código (claves permitidas, `parsePlan` sanitiza y acota todo) en vez de confiar en el LLM (`src/lib/ai-prompts.ts`) — con el hueco puntual del hallazgo 4.

Verificado también sin hallazgo: paridad i18n exacta es/en/de (287 claves por idioma, placeholders idénticos, comprobado programáticamente); `assertSameOrigin` + cookies SameSite=Lax correctos; zod presente en todos los bodies y query params de las rutas leídas.
